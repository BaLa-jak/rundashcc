# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**RUNDASHC** ("Práctica #8") is a 2D autorunner built in Unity **6000.6.4f1** (URP 2D Renderer, new Input System only). The player is the rat **Camarada**. The whole look is an ASCII terminal made of lines of code. All in-game text and code comments are in **Spanish**.

## Commands

`Tools/unity.sh` runs Unity in batchmode. Only one Unity instance can open the project at a time, so the script takes a lock and aborts if the Editor has the project open. Close the Editor before running it.

```
Tools/unity.sh compile   # import + compile; prints "error CS" lines
Tools/unity.sh scenes    # regenerate the 5 scenes + Build Settings (RunDashC.EditorTools.SceneBuilder.BuildAll)
Tools/unity.sh test      # PlayMode tests (Assets/Game/Tests/SmokeTests.cs); results in Logs/test-results.xml
```

To run a single test, call Unity directly with `-runTests -testPlatform PlayMode -testFilter <TestName>`. Copy the other arguments from `Tools/unity.sh`.

Asset generators (Python). Use plain `python3`, not `-I`: PIL lives in the user site-packages.
- `python3 Tools/art/process_sprites.py`: turns `Assets/*.jpeg` into transparent PNGs in `Assets/Game/Resources/Art/`.
- `python3 Tools/audio/generate_audio.py`: synthesizes all SFX and music WAVs (deterministic) into `Assets/Game/Resources/Audio/`.
- `python3 Tools/level/generate_levels.py`: regenerates levels 2–5 (deterministic, difficulty table `LEVELS` inside: speed, spacing, obstacle mix, checkpoints). Every obstacle is kept only if `simulate.py` still finds a no-hit route. Don't hand-edit `nivel2..5.txt`.
- `python3 Tools/level/simulate.py [ruta]`: replicates `CamaradaController`/`RunTuning` physics and checks each level can be cleared without hits (input every 60 ms, hazards +0.1 u, 8 phases for moving hazards). Keep its constants in sync with `RunTuning` and the hazard colliders.
- `python3 Tools/level/check_level.py`: validates every `nivel*.txt` against the jump/gap rules (double jump counts as taught from level 2).

## Architecture

All game code lives in `Assets/Game/`.
- `Scripts/` is the `RunDashC` asmdef (runtime).
- `Editor/` is `RunDashC.Editor`.
- `Tests/` is `RunDashC.Tests`.

**Scenes are generated by code.**
- `Editor/SceneBuilder.cs` and the per-scene builders (`MenuSceneBuilder`, `LevelSelectSceneBuilder`, `GameSceneBuilder` → `HudBuilder`, `GameOverSceneBuilder`, `HelpSceneBuilder`) build `Assets/Game/Scenes/*.unity`. You can also run them from the Editor menu `RunDashC > Construir escenas`.
- Rebuilding **overwrites manual scene edits**. Change the builder, not the `.unity` file.
- Builders wire references through public fields. Button listeners are attached in `Awake`.

**Persistent bootstrap.** `Core/GameBootstrap.cs` uses `[RuntimeInitializeOnLoadMethod(BeforeSceneLoad)]` to create `[RunDashC]` (DontDestroyOnLoad), which holds `AudioManager`, the `EventSystem` + `InputSystemUIInputModule`, and `ScreenFader`. **Scenes must not contain their own EventSystem.** Any scene can be played on its own.

**Shared contracts** (`Scripts/Core/`):
- `GameSession` holds the static run state: player name, level, lives (3), bits and record (record and name are stored in PlayerPrefs). It fires `Changed` whenever any of these change.
  - Per-level max progress 0..100 lives in PlayerPrefs `rdc.lvlN` (`LevelProgress`/`RecordProgress`; 100 = reached the goal). `IsUnlocked(LevelCount)` needs every earlier level at 100. `SceneFlow.Load` calls `PlayerPrefs.Save()`.
- `RunEvents` carries gameplay → HUD events: countdown, progress, hit, checkpoint, level complete, died.
- `SceneFlow` handles navigation with a fade. **Pause = the `Help` scene loaded additively over `Game` with `timeScale = 0`.**
  - `Resume()` unloads Help.
  - Readers of the Pause action must ignore it when `Time.frameCount == SceneFlow.ResumedFrame`.
- `AudioManager.Play(Sfx)` / `PlayMusic(Music)` load `Resources/Audio/sfx_<snake_case>` and `music_<name>`.
- `RunTuning` holds the physics constants that the level design depends on.

**Game flow.**
- `Menu` (name, INICIAR) → `Niveles` (level select, `LevelSelectController`) → `GameSession.StartLevel(n)` → `Game` (countdown → run).
- Pause (`Help`): REANUDAR or SALIR → `Niveles`.
- 0 lives → `GameOver`. REANUDAR = `RetryLevel`; SALIR → `Niveles`.
- Reaching the goal → zoom + victory dance → panel → back to `Niveles`. Level N loads `Resources/Levels/nivelN.txt` and falls back to `nivel1`; speed is ×(1 + 0.15·(N−1)). `GameSession.LevelCount` and `LevelSelectController.Files` must match the level files.

**Levels are text files.** The format is documented in `Core/LevelData.cs`:
- 12 rows between `map`/`end`; the bottom row is y=0; 1 char = 1 unit.
- Legend: `= ^ B S s Z z * C F P`.
- `hint <col> <y> <text>` places in-world text.
- At runtime `Gameplay/LevelBuilder.cs` turns the map into objects. The camera y is fixed so rows 0–11 fill the screen.

**Gameplay** (`Scripts/Gameplay/`):
- `RunManager` is the state machine (Countdown/Running/Dying/Completed) and exposes `Instance`. It handles hits, respawns and the pause input.
- `CamaradaController` handles physics (auto-run, variable jump, double jump, stomping bugs). `CamaradaFx` holds the procedural animation.
- Hazards derive from `Hazard`.
- `AsciiParticles` is a pooled `TextMesh` FX system.

The HUD lives in `Scripts/Hud/` and the menu/game-over/pause UI and widgets in `Scripts/UI/`.

## Conventions and gotchas

- **Domain reload is disabled** (Enter Play Mode Options). Every `static` field must be reset in a `[RuntimeInitializeOnLoadMethod(SubsystemRegistration)]` method, and static-event subscribers must unsubscribe in `OnDisable`/`OnDestroy`.
- **Input:** use only `InputSystem.actions.FindAction("Player/Jump" | "Player/Pause")`. `UnityEngine.Input` throws.
  - Jump = Space/W/Up/LMB/touch/gamepad South.
  - Pause = Esc/P/Start.
- **APIs:** use Unity 6 names: `Rigidbody2D.linearVelocity` and `FindFirstObjectByType`.
- **Text:** use legacy uGUI `Text`/`InputField` plus world `TextMesh`, all with the **VT323** font (`AsciiTheme.Font`). No TextMeshPro. VT323 covers ASCII + Latin‑1 (á é í ó ú ñ) but has **no block or box-drawing chars or arrows (█ ─ ↑)**.
- **Style:** colors come only from `AsciiTheme`. Build UI with `AsciiUi` (canvases are Screen Space–Camera so URP Bloom makes the text glow).
- **Time:** anything that animates during pause must use unscaled time.
- **Sprites:** load with `Resources.Load<Sprite>("Art/<name>")` at PPU 100. Import settings are forced by `Editor/SpriteImportSettings.cs`. Unity reimports by content hash, so `touch` alone won't apply new importer settings.
- **Generated files:** `*.csproj`, `*.slnx`, `Library/`, `Logs/`, `Temp/` and `UserSettings/` are generated and gitignored.
- **`Assets/Editor/HubForceResolve.cs`** was a one-shot Unity Hub bootstrap that deleted itself. Its deletion is expected.
